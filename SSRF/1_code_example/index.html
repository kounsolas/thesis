Server-Side Request Forgery (SSRF)

The backend proxies any URL you provide. Attackers can force the server to make requests to internal services or metadata endpoints — CWE-918. 

{ }

Try These

  • https://example.com — normal outbound fetch.
  • http://localhost:3009/internal/secret — hits an internal-only route.
  • http://169.254.169.254/latest/meta-data/ — discuss cloud metadata exposure.

Fix Ideas

  • Disallow arbitrary URLs; use allowlists for required domains.
  • Block internal IP ranges / metadata addresses at the proxy layer.
  • Use SSRF-aware libraries and apply network-layer egress controls.
